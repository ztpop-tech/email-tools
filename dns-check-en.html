About This Tool

This tool queries email-related DNS records of a domain in real time via DNS-over-HTTPS (DoH). All queries run in your browser; no query data is recorded or stored.

Checks cover SPF (RFC 7208), DKIM (RFC 6376), DMARC (RFC 7489), MX (RFC 5321 §5), PTR (RFC 1912 §2.1), BIMI (RFC 9608), MTA-STS (RFC 8461), TLS-RPT (RFC 8460), DNSSEC (RFC 9364) and DANE (RFC 7672).

For deeper system-level diagnostics or mail system architecture optimization, please see the Knowledge Base or contact us via the footer.

Why Run Regular Checks

A mail system DNS configuration is a combination punch: MX decides delivery routing, SPF/DKIM/DMARC decide authentication trust, MTA-STS/DANE decide transport encryption, PTR reverse DNS affects some anti-spam policies, and DNSSEC guarantees the integrity of all the DNS queries above.

Any missing or broken piece can cause delivery failure, spam-folder placement, or man-in-the-middle attacks. DNS troubleshooting is often the most time-consuming, because errors hide in details like TTL, record types, and even case sensitivity.

This tool queries 10 categories of critical records in one pass and gives a combined diagnosis across three dimensions — authentication, transport and delivery — helping you locate the problem area quickly before digging deeper.

Common Configuration Errors & Fixes

  • Missing MX: add an MX record pointing to your mail server, starting with priority 10
  • Missing SPF: add v=spf1 mx ~all or extend per your sending architecture
  • Missing DMARC: start with p=none, observe reports, then upgrade gradually
  • Missing PTR: contact the ISP owning the IP to add reverse DNS; it must match forward resolution
  • DNSSEC disabled: enable DNSSEC at your registrar/host, watch DS record synchronization
